# Optional PP-OCRv6 Windows engines

Independent Cargo workspace; root application checks do not build ORT or fetch
models. Each release executable embeds exactly one tier's ONNX graphs and YAML
dictionary. The store still installs one file. System `ocr` remains the feature
gate and default; installing a tier replaces the other tiers without clearing
recognized history. Disabling/uninstalling a tier selects the system engine.

## Build (Windows x64)

Prerequisites: Rust 1.96, Python 3.14, Git, Visual Studio C++ x64 build tools and
Windows SDK. Start an **x64 Native Tools Command Prompt**, then:

```bat
cd /d D:\Project\KwikPaste\extensions\ppocr
python -m venv .cache\python
call .cache\python\Scripts\activate.bat
python -m pip install -r requirements-build.txt
python fetch_models.py
python build_ort.py
cargo build --locked --release
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
```

Outputs: `target/release/kwikpaste-ext-ocr-{tiny,small,medium}.exe`. Do not copy
ORT DLLs or models alongside them. `--licenses` prints the embedded ORT and
PaddleOCR notices; ordinary startup keeps stdout protocol-only.
`.cargo/config.toml` sets `+crt-static` and
`ORT_PREFER_DYNAMIC_LINK=0`; `ORT_LIB_LOCATION` points to the local source build.
The release workflow uses the same recipe and an ORT/model cache keyed by ORT
version, target, operator configuration, recipe and model manifest.

`models.json` pins official PaddlePaddle Hugging Face revisions, sizes and SHA-256
for all model/config bytes. `fetch_models.py` checks cached files too. Optional
`--prototype-cache PATH` seeds this cache from the existing prototype, with the
same verification. Models and ORT binaries are ignored, never committed.

ORT source: Microsoft `v1.31.0`, commit
`402979ac1bef89dcd55add41eaa7277c407599eb`. CPU only, Release, `/MT`, telemetry
disabled, no DirectML/CUDA/TensorRT. `required_operators.config` is generated by
`generate_ops.py` from the six graphs plus the CPU level-3 fusion kernels observed
with ORT 1.31. Reduced kernels retain the ONNX loader; **no minimal build** (that
would discard ONNX loading). Built static component/dependency archives are merged
with `lib.exe` for ort's supported single-static-library linking path; ordinary
linker dead-code elimination still applies. Upstream dependency archive checksums
come from the pinned ORT `cmake/deps.txt`.

Only **Windows x64** is released. This machine has no MSVC ARM64 compiler, so
there is no validated ARM64 artifact; the workflow does not register one. macOS
continues using the existing system OCR extension. An ARM64 toolset is required
before testing the recipe's `--target aarch64-pc-windows-msvc` option; override
`ORT_LIB_LOCATION` to that build and use the corresponding Rust target.

## Repeat the measurements

Keep the original prototype's 41-image dataset and official reference JSONs:

```bat
python measure.py --prototype D:\Project\KwikPaste-ppocr-proto --repeats 3
```

This imports the unchanged prototype benchmark, verifies image hashes, spawns only
the specified EXEs, checks output parity against both historical Rust and official
PaddleOCR 3.7, and writes `results/final-*.json` here (never into the prototype).
Parity gates: aggregate normalized divergence <=1%, every image <=10%, identical
line counts. See [MEASUREMENTS.md](MEASUREMENTS.md) for the final measured build.
The memory experiment used one pass with both `with_arena_allocator` and
`with_memory_pattern` set to `true`, then one with both `false`; final code keeps
both `false`. To repeat the ON control, temporarily change those two calls in
`src/lib.rs`, rebuild, and use `--label arena-on --repeats 1`; restore/rebuild
before final measurements. The six original experiment records are retained.

For debug development installation, copy the release tier EXEs next to
`target/debug/KwikPaste.exe` in the root checkout. The existing dev catalog exposes
them as `0.0.0-dev`. An isolated actual-app OCR check uses both gates:

```bat
set KWIKPASTE_SELFTEST=1
set KP_OCR_DEMO_DIR=D:\Project\KwikPaste\crates\kwikpaste-ext-ocr\fixtures\ocr
set KP_OCR_DEMO_VERIFY=1
set KP_OCR_DEMO_MODE=fresh
set KP_OCR_DEMO_ENGINE=ocr-tiny
target\debug\KwikPaste.exe --selftest-ocr-demo
```

Run this last command from the repository root; also place the baseline
`kwikpaste-ext-ocr.exe` in `target/debug`. The demo has its own application identity
and does not read/write the system clipboard or production data. No UI changes
are required. Publication/signing is performed only by the existing release
workflow; building locally does not publish anything.
